# MemSpark 安全边界

## 内存优化

当前版本只保留一个模式：内存优化。该模式的唯一目标是把内存占用压到 25% 或以下。

优化流程会先执行进程工作集整理，再执行系统级释放，包括清空系统工作集、刷新 Modified Page List、清理低优先级 Standby List 和 Standby List。若目标仍未达成，会处理非系统后台候选进程。

## 系统边界

MemSpark 不注入进程，不修改其他进程内存，不删除程序数据。系统关键进程、MemSpark 自身和内部硬边界进程不会被处理。

内部硬边界包括 `System`、`Idle`、`Registry`、`smss.exe`、`csrss.exe`、`wininit.exe`、`services.exe`、`lsass.exe`、`winlogon.exe`、`fontdrvhost.exe` 和 `dwm.exe`。

## 使用代价

工作集整理和系统缓存释放可能导致后台程序重新活跃时出现缺页和短暂卡顿。候选进程处理可能导致未保存数据丢失。

## 不建议使用的场景

- 正在进行游戏、直播、录制或会议时。
- 虚拟机、数据库、Docker、WSL 正在执行关键任务时。
- 编译、渲染、训练、压缩等高负载任务进行中。
- 机械硬盘设备上频繁切换大型程序时。
- 用户不了解工作集整理、系统缓存释放和候选进程处理代价时。
