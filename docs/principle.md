# MemSpark 原理说明

## Windows working set 是什么

Working set 是进程当前驻留在物理内存中的页面集合。一个进程的虚拟地址空间可能很大，但并不是所有页面都会同时驻留在物理内存中。Windows 会根据访问情况、内存压力和调度策略在物理内存、待机页、页面文件或映射文件之间管理这些页面。

## EmptyWorkingSet 做了什么

`EmptyWorkingSet(hProcess)` 会请求 Windows 尽量从目标进程的 working set 中移出可修剪页面。被移出的页面并不等于数据被删除，也不等于进程内存被破坏。进程仍然保留自己的虚拟内存映射和真实内存需求。

## 为什么任务管理器内存占用会下降

任务管理器常见的进程内存列会受到 working set 大小影响。当 working set 被修剪后，目标进程当前驻留在物理内存中的页面减少，因此看到的占用可能下降。

## 为什么这不等于程序真实内存需求降低

工作集修剪不改变程序分配的数据结构、缓存对象、堆内存、映射文件或业务逻辑。程序重新访问被移出的页面时，Windows 会按需把页面调回。真实需求仍然存在，只是暂时不驻留在物理内存中。

## 为什么会产生卡顿

当被修剪的程序重新活跃时，访问不在物理内存中的页面会触发缺页。如果页面来自页面文件或映射文件，系统需要从存储设备读取。SSD 上通常较短，机械硬盘上更明显，可能表现为窗口短暂卡顿、游戏切回延迟或 IDE 响应变慢。

## 为什么适合启动大型程序前使用

启动大型游戏、IDE、虚拟机或编译任务前，临时提高可用物理内存可以减少新任务启动初期的内存竞争。MemSpark 的适用场景是用户明确知道将要启动一个高内存任务，并愿意接受后台程序重新活跃时的缺页代价。
