# 轻存 · MemSpark 清理原理

**简体中文** | [English](principle.en.md) · [返回首页](../README.md)

## 工作集是什么

进程的工作集是它当前驻留在物理内存中的页面。进程申请的虚拟内存不一定都在物理内存里；Windows 会根据访问情况和内存压力管理这些页面。

MemSpark 通过 Windows API 请求整理工作集，优先使用 `EmptyWorkingSet`，失败时尝试 `SetProcessWorkingSetSizeEx`。移出的页面由 Windows 继续管理，程序分配的数据结构和虚拟内存需求不会因此消失。

## 为什么清理后占用会下降，又会回升

工作集变小，会让进程当前驻留的物理内存减少。程序再次访问这些页面时，Windows 会把它们重新加入工作集。页面可能仍在内存中，也可能需要从文件或页面文件读取；后者可能带来磁盘访问和短暂卡顿。

所以，占用下降是一次状态变化，不能直接说明程序运行更快，也不能修复程序本身的内存泄漏。

## 系统级释放

整理进程工作集后，MemSpark 会根据当前内存占用安排系统释放步骤，包括：

- 整理系统工作集。
- 刷新修改页列表。
- 清理低优先级待机列表和待机列表。

这些操作需要相应的 Windows 权限。执行顺序和轮次会随内存压力变化；某一步也可能因权限或系统限制失败。报告和日志会记录相关结果。

## 25% 目标和结束进程

当前实现把物理内存占用不高于 25% 作为目标。如果系统释放后仍未达到目标，会进入候选进程关闭阶段：先请求关闭窗口，必要时强制终止，再继续尝试系统释放。

结束进程会让该程序失去继续运行的状态，和整理工作集不同。未保存内容可能丢失。不能把整个清理流程理解成只调整缓存。候选进程有内部排除规则，但关闭阶段没有通用的前台窗口保护。

25% 也不是可以保证的结果。系统保留、驱动、内核和无法处理的进程都会影响最终占用。

## 报告中的数字

进程工作集减少量和整机可用内存变化是不同指标，不能相互替代。清理期间其他程序也在运行，前后快照记录的是当时的系统状态，而不是精确隔离出来的性能测试。

是否值得清理，应结合实际响应速度和后续任务判断，不必仅为了让占用数字更低而反复执行。操作方法见[使用手册](user-manual.md)。
